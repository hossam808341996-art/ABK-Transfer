# ABK Transfer — نسخة جاهزة للرفع إلى Render

مشروع نقل ملفات ودردشة بين جهازين باستخدام **Node.js + Express + WebSocket (ws) + WebRTC**، بواجهة عربية/إنجليزية من دون تسجيل حساب. هذا المجلد جاهز للرفع إلى GitHub ثم النشر بوصفه **Web Service** على Render.

## ملفات المشروع

- `server.js` — سيرفر الموقع وغرف الاتصال وإشارات WebRTC واحتياط نقل الملفات عبر WebSocket.
- `public/index.html` — واجهة الهاتف والكمبيوتر، ولم يتم تغيير تصميمها.
- `package.json` — الحزم وأوامر التشغيل والاختبار.
- `.node-version` — Node.js 22.
- `render.yaml` — إعداد نشر Render تلقائيًا (Blueprint).
- `tests/server.test.js` — اختبار صفحة الموقع والاتصال والدردشة والإشارات ونقل البيانات والحماية من الاتصال عبر موقع آخر.
- `.gitignore` — يستبعد الحزم والأسرار من Git.

## الطريقة الأسهل للنشر

1. فك ضغط الملف `ABK_Transfer_Ready_For_Render.zip`.
2. أنشئ مستودعًا **Private** جديدًا على [GitHub](https://github.com/new) باسم `abk-transfer` (أو أي اسم تختاره).
3. ارفع **الملفات الموجودة داخل مجلد `abk`** إلى جذر المستودع، وليس ملف ZIP نفسه. يجب أن يكون `package.json` و`render.yaml` في الجذر و`index.html` داخل `public/`.
4. افتح [Render Dashboard](https://dashboard.render.com)، اختر **New > Blueprint**، واربط مستودع GitHub. ملف `render.yaml` يتعرف على إعدادات خادم Node تلقائيًا.
5. وافق على نشر خدمة **abk-transfer** بخطة **Free** إذا كانت متاحة لحسابك.
6. عند نجاح النشر، ستجد **الرابط الحقيقي الخاص بك** في لوحة Render وينتهي عادةً بـ `.onrender.com`. افتحه من جهازين، واختر إرسال في أحدهما واستقبال في الآخر.

### النشر اليدوي بدل Blueprint

- **New > Web Service** ثم اختيار المستودع.
- Language/Runtime: `Node`.
- Build Command: `npm install --omit=dev`.
- Start Command: `npm start`.
- Health Check Path: `/healthz`.
- Instance Type: `Free` للاختبارات أو خطة مدفوعة للاستخدام المتواصل.
- متغير بيئة اختياري: `NODE_ENV=production`.
- لا تضف متغير `PORT` بنفسك؛ Render يضبطه تلقائيًا.

## التشغيل والاختبار على الكمبيوتر

يتطلب Node.js 20 أو أحدث (مفضل Node.js 22).

```bash
npm install
npm test
npm start
```

ثم افتح `http://localhost:3000`. يمكن اختبار اتصال خادم الموقع من `http://localhost:3000/healthz`؛ يجب أن يرجع `ok`.

## من الهاتف

لا تحتاج إلى APK. افتح رابط HTTPS النهائي من متصفح هاتف الإرسال والهاتف المستقبل. لا تشترط أن يكون الجهازان على نفس شبكة Wi-Fi؛ لكن قد تختلف سرعة الاتصال حسب نوع الشبكة والتغطية. لتشغيل اختبارات `npm test` تحتاج بيئة Node.js، بينما المستخدم النهائي يكتفي بفتح الموقع.

## الأمور التي يجب معرفتها قبل مشاركة الرابط علنًا

- **كود من 3 أرقام سهل التخمين، وليس كلمة مرور آمنة.** هناك تحديد لمحاولات الانضمام، لكن هذا لا يجعل نقل الملفات الحساسة آمنًا. إصدار لاحق ينبغي أن يقدم كودًا أطول وموافقة صريحة من جهاز الإرسال قبل قبول أي جهاز.
- **هذا الإصدار لا يعرض نافذة موافقة**: إدخال الكود الصحيح يربط الجهازين مباشرة حسب منطق المشروع الأصلي. لم تُضف ميزة الموافقة حتى لا يتغير سلوك المنتج دون طلب.
- النقل المباشر يعمل عبر WebRTC عندما تسمح الشبكات؛ وعند فشله تتحول الجلسة إلى **نقل عبر سيرفر Render** باستخدام WebSocket/TLS. لذا النقل ليس مشفرًا من طرف إلى طرف في وضع الترحيل، وقد يستهلك من حصة نقل البيانات في الاستضافة.
- الملفات المنقولة لا تحفظ على قرص الخادم في هذا المشروع؛ الملفات المستقبلة تتجمع مؤقتًا في ذاكرة المتصفح، ولذلك الملفات الكبيرة جدًا قد تستهلك الذاكرة.
- الخطة المجانية على Render قد تتوقف بعد 15 دقيقة من عدم النشاط وتحتاج نحو دقيقة لتستيقظ. أضفنا heartbeat عند إبقاء صفحة الجلسة مفتوحة حتى يظل الاتصال نشطًا قدر الإمكان؛ إعادة نشر التطبيق أو إعادة تشغيل الخادم ستُنهي الغرف القائمة، ويمكن للأجهزة بدء جلسة جديدة.
- لا توجد قاعدة بيانات؛ الغرف والرسائل لا تستمر بعد إعادة تشغيل الخادم. استخدم **نسخة واحدة (instance)** من السيرفر، لأن الغرف في ذاكرة السيرفر نفسه.
- يجب استخدام **HTTPS/WSS** في النشر العام. Render يوفر HTTPS تلقائيًا.
- الوصول العام إلى الموقع لا يعني أن المستخدمين موثَّقون؛ استخدامه مع ملفات عامة أو شخصية غير حساسة فقط حتى يُضاف مستوى حماية أقوى.

## التغييرات في نسخة التجهيز للنشر

- الحفاظ على الواجهة الأساسية ونفس رقم الاتصال (3 أرقام) ونقل الملفات والدردشة.
- تحقُّق من مصدر WebSocket لمواجهة الاتصالات غير المرغوبة عبر صفحات أخرى.
- ترويسات أمان أساسية وإخفاء تعريف Express.
- استخدام عنوان الاتصال المناسب للاستضافة، وHeartbeat للحفاظ على الجلسات النشطة.
- الاعتماد على معلومات عنوان العميل الموثوق بها من Render في تحديد محاولات الانضمام.
- ملفات نشر جاهزة واختبار تكامل للوظائف الأساسية.

## الدعم السريع

- الموقع يفتح ولكن الاتصال لا يعمل: تأكد أن كلا الجهازين يستخدمان **نفس الرابط بالضبط**، وأن خدمة Render نشطة، ولاحظ سجل **Logs**.
- إذا ظهرت `noServer`: افحص توفر `/healthz` وتأكد من السماح باتصالات WSS.
- إذا فشل WebRTC: يمكن للنظام الرجوع إلى WebSocket relay، لكن هذا يتطلب أن يكون الخادم نشطًا؛ الشبكات المقيدة قد تحتاج إعداد TURN لتحسين الاتصال المباشر.
- إذا كان النشر متوقفًا: راجع Build Logs في Render وتأكد من وجود `package.json` في جذر المشروع، وليس داخل مجلد متداخل.

**مهم:** تجهيز الملفات لا يعني أن المشروع تم نشره بالفعل أو أن رابطًا عامًا قد تم إنشاؤه. يبدأ النشر عندما تربط المستودع وتنفذ الخطوات أعلاه.
